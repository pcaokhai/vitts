# Plan 1.1 — Gateway skeleton

Task: `docs/12-implementation-plan.md` M1 / 1.1. Depends: 0.6.
Output: the process boots, serves `/healthz` and `/readyz`, and shuts down cleanly.
No user story completes here; this is the frame every M1 story hangs on.

## Steps

| # | Change | Files | Verify |
|---|--------|-------|--------|
| 1 | Config: env loaded once, validated, process exits non-zero with the offending variable named | `internal/config/` | unit test |
| 2 | Structured logging: zerolog, level from env, JSON in prod and console in dev | `internal/telemetry/log.go` | boot output |

## Decisions

- **`/readyz` is a registry, not a hardcoded list.** The endpoint reports every registered
  check with its own status. 1.1 registers none, so an empty gateway is ready; 1.2 adds
  Postgres, 1.4 Redis, 1.6 the worker pool. The alternative — stubbing three checks that
  always pass — would make `/readyz` lie until the real adapters land.
- **Config only carries what this task uses** (`VITTS_ENV`, `VITTS_HTTP_ADDR`,
  `VITTS_LOG_LEVEL`, `OTEL_EXPORTER_OTLP_ENDPOINT`). Database, Redis and S3 settings
  arrive with the adapters that need them, so a missing variable always fails at the task
  that introduced it.
- **`X-Request-Id` is echoed when a caller supplies one**, generated otherwise, and put on
  every response and every log line. An inbound value is length-capped and filtered to a
  safe character set: it reaches logs, so it is untrusted input.
- **Panic recovery returns `problem+json` with code `internal`** and logs the stack once.
  `docs/14-engineering-standards.md` forbids `panic` in request paths; this is the net
  under that rule, not permission to use it.
- **`depguard` rules are written now**, while the use-case packages do not exist yet.
  They cost nothing today and cannot be retrofitted cheaply once code is in them.

## Added while executing

- **Gateway image and compose service.** `make smoke` already promised a `/healthz` leg
  at 1.1, so the gateway now runs in the local stack rather than only on a laptop.
  Distroless has no shell, so the binary probes itself: `gateway -healthcheck` requests
  `/healthz` on the configured address and exits non-zero on anything but 200.
- **`.dockerignore` excluded `gateway/`**, a leftover from 0.6 when the worker was the
  only image. The gateway build could not see its own source until that was removed.
- **Routing failures keep their protocol status.** `invalid_request` maps to 400, but a
  missing route is 404 and a wrong method is 405. The code stays `invalid_request`
  because it is the closest member of the `Problem.code` enum, and a new code goes in
  `openapi.yaml` first.
