## Decisions

- **Every image is pinned by digest**, including both stages of a multi-stage build. A
  rebuild months from now then produces the same image rather than whatever the tag
  points at by then.
- **The build stage tracks a current Go patch release, not the module minimum.**
  govulncheck reports standard-library advisories against the toolchain that *produced*
  the binary, so an old builder ships known-vulnerable stdlib code even when the source
  has not changed. `go.mod`'s `go` directive stays a minimum for consumers.
- **The production overlay refuses to render when a secret is missing.** `${VAR:?...}`
  turns "someone forgot to set the admin key" into a failure at config time rather than a
  service that quietly started with a development default.
- **Only the gateway and the S3 API publish ports in production.** Postgres, Redis,
  Prometheus, Grafana and the worker are reachable on the compose network alone. MinIO's
  API port stays open because signed download URLs point at it and customers must reach
  it; its admin console on 9001 is closed outright.
- **Containers run read-only where they can.** The gateway and the migrations job get a
  read-only filesystem with a small tmpfs, so a stray write is a visible failure. The
  worker cannot: onnxruntime and `huggingface_hub` write into the model directory, which
  is a named volume.
- **Redis is bounded with `allkeys-lru`.** Everything the gateway stores there is a cache
  or a lease that can be rebuilt, so evicting beats running out of memory (ADR-005).
- **Memory limits and log rotation on every service**, so one runaway process cannot take
  the host down and a chatty incident cannot fill the disk.

## The scanner found real work, then needed a real gate

`govulncheck` reported **20 reachable vulnerabilities**: 19 in the standard library and
one in gRPC. Moving the build image from Go 1.25.14 to 1.26.8 removed all 19 — they were
shipping in the binary purely because the builder was behind.

The remaining one, **GO-2026-6443**, has no stable fix: it exists only in an unreleased
`v1.85.0-dev`. The advisory affects gRPC *servers* running the xDS routing interceptor,
and the only call path govulncheck reports goes through `internal/dispatch/fakeworker`,
a test double. Production registers no gRPC service and configures no xDS.

Rather than pin an unreleased dependency or delete the check, `make audit` gained a small
gate: `security/accepted.yaml` records the finding, the reasoning, and a `review_by`
date. **Anything unlisted fails, and so does any acceptance whose date has passed** — an
exception that cannot expire is a disabled check with extra steps. The script also prints
a note when an accepted finding stops being reported, so the file does not accumulate
entries for things that were fixed years ago.

## Not verified locally

`pip-audit` could not run on this machine: it builds an isolated environment and
`ensurepip` aborts under the uv-managed CPython here. It runs in CI on a normal Linux
Python, which is where the gate matters. The govulncheck half of `make audit` was
verified locally, and the audit script pins `GOTOOLCHAIN` so a developer's toolchain
cannot make the scan disagree with the artefact.
