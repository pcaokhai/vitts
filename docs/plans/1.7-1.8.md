## 1.7 Dispatcher

| # | Change | Files | Verify |
|---|--------|-------|--------|
| 1 | Priority classes, per-class wait budgets | `internal/dispatch/queue.go` | T-46 |
| 2 | Slot reservation that accounts for in-flight work the health poll cannot see yet | same | T-49 |
| 3 | 30% stream reservation | same | T-47 |
| 4 | `Retry-After` from queue depth × mean service time, bounded 1–30 s | same | T-48 |

### Decisions

- **Refuse, never queue past the budget.** Stream waits 2 s, sync 10 s; past that the
  caller gets `ErrOverloaded`. Accepting work we cannot start is the accept-then-timeout
  failure ADR-007 exists to prevent.
- **`BatchWait` is 5 minutes, not unbounded.** ADR-007 says batch "yields to higher
  classes", which is about priority, not about letting a goroutine wait forever.
- **In-flight reservations are subtracted from free capacity.** A worker's health
  snapshot is up to one poll interval stale, so without this the dispatcher would admit
  the same slot several times inside that window.
- **Mean service time is an EWMA**, so `Retry-After` follows current load rather than the
  whole history. It starts at 1 s — roughly a short Vietnamese utterance at the measured
  RTF — so early values are plausible rather than wild.
- **A released slot signals waiters** instead of having them poll, and the signal is
  non-blocking: a waiter that is already awake does not need another.

## 1.8 Cache

| # | Change | Files | Verify |
|---|--------|-------|--------|
| 1 | Key derivation, canonicalised | `internal/cache/key.go` | T-50 |
| 2 | Manager over index, store and catalogue ports | `internal/cache/cache.go` | T-51 |
| 3 | Redis index with sliding TTL | `internal/storage/redis/cacheindex.go` | — |
| 4 | Postgres catalogue for eviction to scan | `internal/storage/postgres/cacherepo.go` | — |
| 5 | S3 adapter (MinIO-compatible, path-style) | `internal/storage/s3/s3.go` | live stack |

### Decisions

- **Canonicalise before hashing.** `0.8` and `0.80` are one temperature, and runs of
  whitespace are one text (US-11 AC-2). Case and punctuation are *not* canonicalised:
  they change how the model speaks, so they must change the key.
- **Model version is in the key** (ADR-006, US-11 AC-3), so an upgrade invalidates the
  cache instead of serving audio from weights that no longer exist.
- **No tenant in the key.** A cross-tenant hit is the design: identical input gives
  identical audio and the audio carries no tenant data.
- **Object first, then catalogue, then index.** An object with no index costs one
  re-synthesis; an index pointing at nothing would send every later caller down the
  stale-entry path.
- **A vanished object degrades to a miss**, and the stale index entry is dropped so the
  next caller pays one lookup rather than two. A deleted object must never turn into a
  failed request.
- **Three ports, not one store.** Redis is the fast index, Postgres is what survives a
  Redis flush and what the eviction job scans (task 2.8), S3 holds the bytes. Collapsing
  them would make eviction impossible to write.

## Fixed while verifying

The `/v1` guard chain was mounted with no routes, and chi runs middleware only for
matched routes — so an unauthenticated request to `/v1/anything` was a plain 404 with no
authentication and no rate limiting, while the wiring *looked* correct. Routes are now
passed in through `Deps.TenantAPI`, which is what puts them behind the chain, and a test
registers two routes and asserts the whole chain: 401 without a key, 403 for a key
missing the scope, 429 with `Retry-After` when throttled, 200 otherwise.
