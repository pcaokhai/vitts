## Decisions

- **Dialing never blocks the boot.** `grpc.NewClient` is lazy, so an unreachable worker
  cannot stop the gateway from starting; it reports itself unready instead. That is what
  FL-06 asks for, and it is also what lets a deploy bring the gateway up before the
  worker has finished loading weights.
- **The gateway does not `depends_on` the worker in compose.** A cold worker takes
  minutes to materialise weights; waiting on it would make the whole stack unavailable
  for that time instead of merely unready.
- **Selection is advisory.** The pool picks by free slots, but the worker is the
  authority on its own slot and answers `RESOURCE_EXHAUSTED` when it loses the race
  (ADR-003). The pool never queues: queueing is task 1.7's decision, and turning
  "no worker" into a wait here would hide overload instead of reporting it.
- **RTF breaks ties between equally idle workers**, so a fleet with one slow node drifts
  traffic away from it. A worker that has served nothing reports RTF 0; it is treated as
  average rather than best, so a cold worker is neither starved nor preferred.
- **`Ready` is about the fleet being alive, not about spare capacity.** A fully busy but
  healthy worker keeps `/readyz` at 200: the gateway can serve as soon as a slot frees,
  and flapping readiness under load would take a healthy gateway out of rotation exactly
  when it is needed.
- **Timings are `Options` with the FL-06 values as defaults.** Tests shorten the
  intervals, which are tuning, and keep the failure threshold, which is behaviour.

## Fixed while writing it

- The first draft scheduled the next probe from the last *successful* probe, so a failing
  worker was permanently overdue and spun the poll loop at tick rate. Probe time is now
  tracked separately from last-seen.
- `Close` returned an error on a second call, because closing an already-closed gRPC
  connection fails. Shutdown paths overlap, so `Close` is now idempotent and caches its
  result.
