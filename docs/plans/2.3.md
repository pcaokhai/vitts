## Decisions

- **Idempotency compares a body fingerprint, not the raw bytes.** A client that reorders
  JSON fields or reformats whitespace is asking for the same job, and should get its
  original back rather than a 409 (US-14 AC-1). The fingerprint lives on the job's
  metadata under an internal key that is stripped before the job is shown.
- **The text itself is never hashed into anything stored.** The fingerprint covers
  canonicalised text, and the text goes to object storage (ADR-008).
- **Text is stored before the row exists.** A job row pointing at text we failed to write
  would be unrunnable; orphaned text is swept by the lifecycle rule instead.
- **The queue is the last step.** A queued id with no row makes the orchestrator chase a
  ghost; a row nothing queued is picked up by the reconciler, which is the recoverable
  direction. A queue failure therefore logs and still returns the job.
- **A lost race on the unique index returns the winner's job**, not an error: both
  callers asked for the same work.
- **Cancelling an already-terminal job succeeds.** A client retrying a cancel it is
  unsure about should not be punished for succeeding twice.
- **Another tenant's job is `job_not_found`**, and so is a malformed id — answering
  differently would confirm which ids exist (docs/07-permissions.md, T-12).
- **The SSRF guard resolves and checks every address.** A hostname that answers with one
  public and one private address is the classic bypass, so all answers must pass.
  Loopback, RFC1918, link-local (the cloud metadata endpoint), CGNAT, IPv6 unique-local,
  multicast and unspecified are all refused, and only HTTPS is accepted — a signed body
  sent in the clear is still readable.
- **Streams are capped at 100,000 entries.** A backlog that long means the orchestrator
  is down, and recovery comes from Postgres via the reconciler rather than from an
  unbounded stream.
