## Decisions

- **Every refusal happens before the first byte.** Once the header is written the status
  is committed, so quota, concurrency and voice checks all run first. After the first
  byte the only honest option left is to truncate and log, which is what the handler
  does — a problem document appended to audio would corrupt the stream.
- **The client's context is the cancellation signal end to end.** A disconnect cancels
  the gRPC call, so the worker stops within one frame (T-02 already pinned that side).
- **Partial audio is never cached.** A cancelled stream discards its tee buffer: a cache
  entry holding half an utterance would be served to the next caller as if complete.
- **A cancelled stream is billed from delivered audio** at ADR-010's published rate,
  capped at the request's characters. A client hanging up is not a server error, so the
  handler returns normally and the usage row carries `client_cancelled`.
- **The lease is released on a cancelled request too**, using `context.WithoutCancel`, so
  capacity returns immediately rather than after the 60 s TTL. It is renewed every 20 s
  while the stream runs, well inside that TTL.
- **The meter never blocks the caller.** A full queue drops records and counts them:
  metering is valuable, but not so valuable that a stalled database should stall
  synthesis. Dropped batches are logged with a running total.
- **The meter drains on shutdown.** Requests that happened must not be forgotten because
  we deployed, so `Stop` empties the queue before returning.
- **Usage inserts are idempotent on `(id, created_at)`**, so a retried batch cannot
  double-bill (docs/05-data-model.md § 4). The batch runs in one transaction with one
  statement per row: it is already off the request path, and correctness beats a round
  trip here.
