## Decisions

- **Cancellation granularity is one frame.** Upstream `synthesize_stream` is a plain
  generator with no interrupt, so the flag is checked between frames and the generator is
  then closed. Measured worst case is well inside the 200 ms budget; the test asserts the
  budget, not the measurement.
- **`asyncio.shield` around each `next()`.** When the client cancels, the error must
  reach the servicer while the worker thread finishes its frame — closing a generator
  that is still executing raises `RuntimeError`. The `finally` block waits for that
  in-flight frame before closing and releasing the slot.
- **A busy worker returns `RESOURCE_EXHAUSTED` immediately** rather than queueing
  (ADR-007: overload fails fast, it never accepts then times out). Queueing is the
  gateway dispatcher's job in task 1.7.
- **Resampling carries 64 input samples of filter context across chunks** and pins total
  output to the exact ratio, so per-chunk rounding cannot drift over a long stream.
  Measured drift: 0.0000% at 8/16/24/48 kHz.
- **`chars_consumed` on a cancelled stream is an estimate at 14.5 chars/s**, the floor of
  the measured range, so a cancelled request under-bills rather than over-bills. A
  completed stream always reports the exact character count. See the open question below.

## Measured on the target machine (MacBook M4 Pro, 8 ORT threads)

4 voices × 3 text lengths, native 48 kHz:

| | min | max | mean |
|---|---|---|---|
| TTFA | 43 ms | 70 ms | 55 ms |
| RTF | 0.32× | 0.40× | 0.36× |
| speaking rate | 14.6 chars/s | 25.8 chars/s | 18.2 chars/s |

Budget is 150 ms TTFA (US-01 AC-2) and RTF < 1.0. `docs/reports/bench-m0.md` from task
0.5 remains the authority.

## Open question for ADR-006 (billing)

Upstream reports no text position during streaming, so exact partial metering of a
cancelled request is not derivable. This task bills cancelled streams from audio produced
at a fixed conservative rate. If billing needs to be exact, the alternative is to charge
cancelled requests nothing below some audio threshold, which is a pricing decision, not
an implementation one.
