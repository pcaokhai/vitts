## Decisions

- **Readiness is the `Health` RPC.** A worker that is listening but still loading weights
  must fail the probe, otherwise compose would report it up and the gateway would route
  to a worker that cannot serve (US-02 AC-1).
- **`.env.example` is the compose env file** (`--env-file`), so the pinned revision and
  the local dev credentials exist in exactly one place. `deploy/.env` was removed for
  the same reason.
- **MinIO comes from quay.io, pinned by digest.** The Docker Hub tags in the first draft
  did not resolve; quay.io is MinIO's own registry.
- **Model weights live in a named volume**, so a container restart does not re-download
  ~200 MB. First boot on a clean volume takes ~150 s on this machine, which is why the
  health check allows 30 retries.

## Fixed here

`VITTS_GRPC_ADDR` defaulted to `:50051`, Go's syntax. `grpc.aio` cannot bind a bare
`:port` and the container crashed on startup. The fix normalises the address in
`config.py`, so compose, `.env.example` and the docs can keep the Go-style form that
`VITTS_HTTP_ADDR` uses. Covered by a test.

## Verified

```
make up     → postgres, redis, minio, worker all healthy
make smoke  → Health ready; Synthesize 7 frames, 3.12 s audio, TTFA 88 ms, RTF 0.55x
```

RTF is higher than the 0.32× measured natively: the worker runs under the Docker Desktop
VM here. On Linux hosts the container shares the host kernel and this gap disappears.
