## Decisions

- **Every step is idempotent, and state lives in Postgres.** A crash resumes from the row
  rather than restarting the work: a replayed job entry re-fans-out only unfinished
  segments, and a replayed segment entry fails its claim and costs nothing (T-09).
- **`ClaimSegment` is the concurrency control.** It is a conditional update, so two
  consumers racing the same entry produce exactly one synthesis.
- **`CompleteSegment` marks the segment and increments the job counter in one
  statement**, so `segments_done` can never disagree with the segments themselves
  (docs/05-data-model.md § 4).
- **Stream entries are acknowledged even when the work failed.** The failure is recorded
  on the job row; leaving the entry pending would have the reconciler replay it forever.
- **Jobs dispatch at `ClassBatch`**, so an interactive stream always outranks them
  (ADR-007). A long job cannot starve a live caller.
- **Segments go through the audio cache**, keyed exactly as a sync request is, so a
  phrase a tenant already synthesized costs nothing the second time (ADR-006).
- **The reconciler re-queues rather than repairs.** Because every step is idempotent,
  pushing a stalled job back through the front door is safer than a special recovery
  path that would be exercised only during incidents.
- **Input text is deleted when a job reaches a terminal state**, and a failure to delete
  is logged rather than propagated — the bucket's lifecycle rule is the backstop
  (US-14 acceptance criterion 4).

## Two defects found by running it

- **Retry counted one attempt too few.** `ClaimSegment` increments `attempts` before the
  work runs, and the retry check added one again, so a segment failed the job after two
  tries instead of three. A test asserting `attempts == 3` caught it.
- **Signed download URLs pointed at `http://minio:9000`** — the name the gateway uses
  inside the compose network, which no customer can resolve. US-14 acceptance criterion 4
  promises a usable link, so signing now happens against a separate public endpoint
  (`VITTS_S3_PUBLIC_ENDPOINT`). The same split exists in production between a VPC
  endpoint and the public one, so this is not a compose-only fix.
