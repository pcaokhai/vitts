## Decisions

- **Migration 0001 seeds no plans.** The first draft invented four tiers with prices;
  `docs/01-PRD.md` defines no tiers at all, it only quotes a competitor at $16 per
  million characters. Fabricated pricing in a migration would reach production, so the
  placeholder lives in `scripts/seed.sql` (dev-only, `make seed`) and a test asserts the
  migration ships an empty `plans` table. **Real tiers are an open product decision.**
- **The serving process never migrates on startup.** `docs/13-runbook.md` orders the
  deploy as migrations job → worker → gateway; compose mirrors that with a one-shot
  `migrate` service the gateway waits on. Replicas therefore cannot race over the schema.
- **Migrations are embedded in the gateway binary** (`go:embed`), so the migrations job
  runs the exact schema that ships in the image, with no second image or tool to keep in
  step. `make migrate` uses the same code path.
- **sqlc reads the migrations as its schema**, not a hand-maintained copy. A query that
  outgrows the schema fails at `make generate` instead of at runtime.
- **`ensure_synth_requests_partition(at)`** is a function in the migration, called twice
  to seed this month and next. Task 2.8's maintenance job calls the same function, so
  there is one definition of what a partition looks like.
- **Extra `check` constraints** beyond the data-model doc: name lengths, non-negative
  counters, and `octet_length(...) = 32` on both sha256 columns. A 16-byte "hash" is a
  bug worth catching at the boundary.
- **The `go` directive stays at 1.25.** `goose@latest` requires 1.26; the library is
  pinned to v3.22.1, the version `scripts/setup.sh` already pins for the CLI, so the two
  cannot drift.
