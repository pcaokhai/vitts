## Decisions and findings

- **Weights are materialised with `snapshot_download(local_dir=…)`, not the shared HF
  blob cache.** The cache stores snapshots as symlinks into `blobs/`, and onnxruntime
  refuses the codec's external-data file with *"External data path escapes model
  directory"*. Real files also make the directory safe to mirror to S3 verbatim.
  New variable: `VITTS_MODEL_DIR`.
- **`MODEL_FILE_PATTERNS` excludes `samples/` and `banner.png`** — about 500 MB of demo
  audio that would otherwise sit in every image and every mirror. 37 files → 17.
- **`VITTS_MODEL_REVISION` has no default and boot fails without it.** `main` in
  `.env.example` would have shipped an unpinned worker; the pre-go-live checklist item in
  `docs/08-variables.md` is now enforced by code, not by a checkbox.
- **The server starts before the model loads** so the gateway sees `ready=false` rather
  than connection refused during the ~4 s warm-up.
- ~~Open finding for 2.2: upstream exports no chunker.~~ **Wrong, retracted.**
  `zerotts.chunking.chunk_text(text, max_chunk_sec=15.0)` exists with exactly the
  signature US-03 acceptance criterion 1 names; it is simply not re-exported from
  `zerotts/__init__.py`, which is why a scan of the package's top level missed it.
  `docs/02-architecture.md` was right: `Segment` stays a thin wrapper.
