## Decisions

- **Every authentication failure is one answer.** Unknown key, revoked key, malformed
  credential and suspended tenant all return 401 `unauthorized` with the same detail. A
  caller learns whether it holds a working key and nothing else.
- **A lookup outage is 500, not 401.** If Postgres is unreachable the repository returns
  `ErrLookupFailure` and the middleware maps it to `internal`. Returning 401 during our
  own incident would send every tenant hunting for a credential problem they do not have.
- **A malformed credential never reaches the database.** The prefix check happens before
  the query, so unauthenticated traffic cannot be turned into database load.
- **Tenant, first key and audit entry commit in one transaction.** The first draft wrote
  the audit entry after creation and returned an error if it failed — which would have
  handed back an error while the tenant existed and the secret was already lost. A tenant
  that is not attributable is an audit gap, so all three rows exist or none do.
- **The admin guard requires key *and* network.** The peer address comes from the
  transport, never from `X-Forwarded-For`, which a caller controls. A proxy in front of
  the gateway must therefore be inside the allowlist itself. An empty allowlist denies
  everything: a misconfigured allowlist must close the door, not open it.
- **`VITTS_ADMIN_KEY` under 32 characters or an empty allowlist fails the boot.** The
  pre-go-live checklist in `docs/08-variables.md` asked an operator to remember this; now
  the process will not start without it.
- **`-migrate` and `-healthcheck` read only the variables they need**, not the full
  config. A migrations job has no business holding the admin key, and a health probe must
  keep working when the serving configuration is incomplete.
- **No Redis cache yet.** US-05 acceptance criterion 5 allows a 60 s cache; 1.3 queries
  Postgres every request, which is stricter (revocation is immediate). The cache and its
  invalidation land with Redis in 1.4.
- **Test fixtures build their admin key** with `strings.Repeat` instead of writing a
  32-character literal. gitleaks flagged the literal, and it was right to: a reviewer
  cannot tell a test constant from a leaked key at a glance.

## Found while verifying against the live stack

- **Docker Desktop's host gateway is 192.168.65.1**, outside the `172.16.0.0/12` the
  compose default allowed, so admin calls from the host were denied with `key_ok=true`.
  The guard behaved correctly; the dev allowlist was wrong. `.env.example` now lists the
  private ranges a local stack actually uses, with a note that production narrows them.
- **Published host ports are now overridable** (`VITTS_PG_PORT`, `VITTS_GATEWAY_PORT`,
  …). The stack collided with another project already holding 5432 and 8080 on this
  machine, and a dev stack should not require stopping unrelated services.
