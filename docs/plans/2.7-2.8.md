## Decisions

- **The rollup recomputes, it does not increment.** `insert … on conflict do update`
  over a window means re-running it is free and a missed tick self-heals. The window is
  30 minutes against a 5-minute interval, so a row written moments before a run, or a
  replica that missed one, is still picked up (FL-07).
- **Every replica runs the same schedule and takes a lock first.** The work is
  idempotent, but running the eviction sweep on three replicas would triple the
  object-store traffic for no benefit (T-19).
- **The lock releases only what it still owns.** A plain `DEL` would let a replica whose
  lease expired delete a lock another replica has since taken — the classic way a
  distributed lock stops being one. Release runs a Lua compare-and-delete, on a context
  detached from the caller so a cancelled run still releases.
- **Eviction deletes the object before the row.** A row without its object is a cache
  miss; an object with no row is invisible and would never be deleted. An object that
  fails to delete keeps its row, so the next sweep retries it.
- **Partition maintenance looks two months ahead**, so a missed run cannot leave metering
  with nowhere to write. It calls the function migration 0001 defines, so a partition has
  one definition whether it is created at migration time or by this job.
- **Report windows are UTC days and capped at 366.** Storage is UTC, so reporting is too;
  a tenant asking for years of daily rows would scan more than one response should carry.
- **CSV goes through `encoding/csv`.** It quotes what needs quoting and uses CRLF, which
  is what RFC 4180 asks for. Hand-rolling it is how a comma in a future column becomes a
  corrupt export.
- **Totals are their own type.** Reusing `Day` for them put a zero `0001-01-01` timestamp
  in every response — a total has no date.

## Known gap

The rollup runs once at boot and then every 5 minutes, so usage written just after a run
is invisible until the next one. US-16 acceptance criterion 2 allows a 5-minute lag, so
this is within contract — but it means a freshly started stack shows an empty report
until the first interval elapses, which reads like a bug and is not.
